# Report — P7–P10 Web app (owner panel, kitchen display) and end-to-end tests
Date: 2026-10-30 (Asia/Karachi) · Phase/step: Phase 2, P7–P10 · Author: Claude Code

## 1. Summary
The web app is built and has been checked in a real browser (Chromium) against the real built server and database. I built P7–P9 together because the owner and kitchen pages were needed before the app would compile, so this report covers all four steps.

- **P7 foundation:**
  - Vite 8, React 19, React Router 8 and Tailwind v4, with tokens from the design system and self-hosted fonts.
  - API client (request ids, timeouts, error envelope, schema validation, clock samples) and server-clock sync.
  - One shared 1-second ticker, aligned to the corrected second.
  - The order store, with version checks and tombstones, and the live-sync hook (state machine, snapshot + buffer, resync).
  - Session context and route guards, UI primitives, and the login and pairing pages.
  - The logo, cropped from the menu image (not redrawn), plus a favicon, app icons and a web app manifest (installable).
  - Code-split per screen; the largest chunk is 228 KB (72 KB gzipped).
- **P8 owner panel:**
  - **Paste → review → Send** (Q-02): Paste only fills the box, with Undo when it replaces text. Send is disabled while empty; Ctrl+Enter also sends.
  - Source and target selectors. Sending runs a state machine (sending / checking / saved / failed / "earlier version already sent"): retries reuse the same key, and the unsent draft is kept on the device.
  - Active list with two-tap Complete and a Cancel dialog.
  - History, limited to 7 days, filterable by status and order number.
  - Kitchen screen pairing and disconnecting, header clock and connection pill, and the offline banner.
- **P9 kitchen display:**
  - Oldest-first grid of cards with arrive/leave animation (gentler with reduced motion) and a NEW highlight.
  - Timers in normal, warning and overdue phases, with an OVERDUE badge and one pulse when a card turns overdue.
  - "Yesterday" badge for earlier business days, and an "N more below" hint.
  - Chime after tapping to enable sound (at most one per 2 s), full screen, large-text density, screen wake lock and cursor auto-hide.
  - The kitchen screen has no order controls.
- **P10 end-to-end tests:**
  - 23 Playwright specs on a disposable stack: the built server on the test database, reset on every run, with the owner created by the built CLI; plus `vite preview` proxying the API and sockets on the same origin.
  - Covered: owner→kitchen live delivery, clipboard, complete/cancel, auth and revocation, refresh, offline and catch-up, double-click, timers (including a wrong device clock), latency, accessibility (axe) and screenshots.

## 5. Remaining limitations / open items
- **Bugs found and fixed:**
  - **History search by number didn't work.** A shell-escaping slip turned the `\d` regex into `d`, so the number was never sent. The browser tests caught it; it's fixed and verified.
  - **The overdue timer pill overflowed the card** on 1920-wide screens ("+02:03 OVE…" was clipped). The OVERDUE label is now a badge next to the source, and the timer pill can't shrink or wrap.
  - **React lint findings:** refs were written during render, state was set inside effects, `Date.now()` was called during render, and one callback called itself before it was declared. All were restructured; none are suppressed.
- **Browsers:** the end-to-end run is Chromium only. Firefox and WebKit owner smoke runs are planned (E2E_TESTING) but NOT RUN, because those browsers aren't installed.
- **Server restart:** not covered by an automated end-to-end test. Restarts are covered at the server level (numbering survives a restart) and by the reconnect/offline catch-up spec. A live restart check is part of the P11 prod-like run.
- **Logo quality:** the source menu image is only 859 px wide. The header logo looks sharp, but the 512 px app icon is slightly soft. A high-resolution logo file from the owner would fix that.
- **Business-day cutoff in the browser:** the client uses the default 06:00 cutoff for the "Yesterday" badge and the history date list. If `BUSINESS_DAY_CUTOFF_HOUR` is ever changed on the server, those labels could be off by one day. Numbering itself is always server-side.
