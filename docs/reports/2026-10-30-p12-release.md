## 2. Independent review (one read-only subagent) and fixes
Each finding was checked against the code before fixing.

| # | Severity | Finding | Fix | Verified by |
|---|---|---|---|---|
| 1 | **High** | The production server would refuse to start on the VPS. Compose passes the unset `RKDS_INSECURE_LOCAL` as `""`, and the env schema rejected empty strings | `loadEnv` treats empty variables as unset | New `env.test` case; the built server started with `NODE_ENV=production`, `RKDS_INSECURE_LOCAL=` and an https origin ("server listening") |
| 2 | Medium | After a handshake rejection (a database blip during reconnect), socket.io-client stops reconnecting, so a kitchen screen could stay "Offline" until reloaded | The hook reconnects by itself with backoff when `!socket.active` | 2 new `use-order-sync` tests |
| 3 | Low | The backup/verify/restore scripts passed the file name into `sh -c` with only a loose check | Strict regex `^rkds-(pre-restore-)?\d{8}-\d{6}\.dump$` | Review of the scripts. They were not re-run after this change (Docker down) |
| 4 | Low | A forged history cursor (36 dashes) caused a 500 | Validate the id with the shared `Uuid` schema → 400 | `orders.history.int` case |
| 5 | Low | A typo in `RESTAURANT_TIMEZONE` only failed later, at runtime | Validated at startup | `env.test` case |
| 6 | Low | A throwing socket listener after commit would have turned a saved order into a 500 | Listener errors are isolated and logged (error name only) | `order-events.test` case |
| 7 | Low | Pairing an owner's browser left its owner session alive | `/pair` revokes the browser's previous session | `pairing.int` case |
| 8 | Low | No HSTS header on the Traefik route | Traefik `stsSeconds` middleware label; HSTS line added for host nginx in DEPLOYMENT §4 | `compose:check` |
| 9 | Low / by design | An open owner tab never hits the 24 h idle limit (background resync counts as activity) | Documented as intended in SECURITY §2 (the absolute 7-day limit still applies) | — |

## 6. Deployment: exact commands (when the domain exists)
Run on the VPS, in order. Each step is described in DEPLOYMENT.md.
1. `bash vps-inspect.sh 2>&1 | tee vps-inspect.txt`. This is read-only. Share the output with secrets removed, then choose overlay `traefik` or `host`.
2. `sudo mkdir -p /opt/rkds/backups && sudo chown -R $USER:$USER /opt/rkds && cd /opt/rkds`, then clone or upload the code to `/opt/rkds/app`.
3. `cp app/.env.example .env && chmod 600 .env`, then fill it in:
   - two separate generated passwords
   - `APP_ORIGIN=https://<domain>`, `TRUST_PROXY=2`, `RKDS_VERSION=<sha>`
   - the overlay variables
   - and **no** `RKDS_INSECURE_LOCAL`.
4. Overlay B only: add the nginx server block or Caddy site, then `sudo nginx -t && sudo systemctl reload nginx` and `sudo certbot --nginx -d <domain>`.
5. `source app/scripts/lib/compose.sh && $COMPOSE config -q && $COMPOSE build && $COMPOSE up -d && $COMPOSE ps`
6. `$COMPOSE exec server node dist/cli/create-owner.js`
7. Verify (DEPLOYMENT §7):
   - `curl -fsS https://<domain>/api/health/ready`
   - `rolsuper = f`
   - `db` has no published port
   - n8n and Evolution API still up
8. Install the daily backup cron (BACKUP_AND_RECOVERY §2) and run `scripts/backup.sh` once.
